# 网络设置与代理策略

## 本轮范围

补齐交接路线中的代理设置界面，保留 .NET / WPF 和现有服务分层。游戏与资源下载、元数据、微软认证、Java 下载和更新客户端继续使用共同的 HttpClientFactory；没有添加第三方运行时依赖。

左侧栏和首次安装向导均可打开「网络设置」。支持自动选择、直接连接、自定义 HTTP / HTTPS / SOCKS5 代理。自定义地址不接受用户名密码、路径、查询参数和片段。连接方式与下载源是两个独立选择，选择官方源仍可使用代理。

## 生效与失败行为

- 配置在进程内保持快照。保存后的更改需要重启，避免正在运行的下载和认证流程混用新旧设置。
- 自动模式保留原有系统 / 环境变量检测、按目标记忆连接方式、传输失败后换道一次的行为。
- `MCLAUNCHER_FORCE_DIRECT`、`MCLAUNCHER_FORCE_PROXY`、`MCLAUNCHER_NO_PROXY_PROBE` 仅在自动模式下参与原有策略；界面显式选择的直连或自定义模式优先。
- 自定义模式只使用指定代理，失败直接反馈；直接连接模式不使用系统代理。
- `settings.json` 缺少 proxy 字段时使用自动模式；字段无效时请求明确失败，用户可在网络设置里重新保存。整个 JSON 文件损坏则保留原文件并提示先修复格式。
- 写入先验证、保留其它字段、写同目录临时文件后替换。文件被占用或写入失败时不显示成功，临时配置被排除在 Git 提交范围之外。
- 只影响启动器自己的 HTTP 请求；Windows 代理及游戏进程网络不作改动。

## 启动与资源生命周期

创建客户端仅捕获本地配置，不进行系统代理隧道探测。DeferredHttpHandler 在线程池延迟建立通道，首批并发请求复用同一次初始化，取消某个等待请求不会破坏其它请求。关闭客户端释放连接池，包括初始化未完成时的清理。

本轮没有重新测量真实首帧耗时，不能将历史性能数字当成本轮结果。

- WPF 检查：88 项通过。覆盖保存、重新打开、未保存编辑、占用失败后重试、重启提示及当前进程策略不变。

测试使用虚构配置和隔离临时目录。HTTP 代理已通过本机实际请求检查；HTTPS / SOCKS5 本轮验证地址格式并交由 .NET 网络实现处理，未进行真实代理服务、微软登录或全量游戏安装验收。

## 后续路线

多账号管理和代理设置已落地。后续优先推进更新清单签名与发布密钥管理；正式发布前仍需真实网络安装、登录、启动及性能验收。CurseForge 检索权限取决于 API Key，增量差分和主题美化暂不在本轮范围。
