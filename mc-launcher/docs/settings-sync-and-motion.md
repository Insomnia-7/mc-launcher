# 游戏设置同步与统一动效 · 0.9

## 使用步骤

1. 在「设置 → 游戏同步」选择常用的游戏实例作为来源，选择要共享的按键、音量、画面、语言或服务器列表，保存共享来源。来源游戏需要已经运行过，生成相应设置文件。
2. 选择另一个实例，勾选「此实例使用共享设置」和跟随内容，保存实例选项。默认不启用任何实例；画面与服务器列表默认不勾选。
3. 点击「预览同步差异」。首次不同的值作为冲突，默认保留本地；勾选后才采用共享值。未勾选的差异会保存为实例例外，可以在「保留本实例的独立设置」中调整。
4. 应用时自动备份将修改的文件。之后每次启动跟随实例前，会读取共享方案，并更新未独立修改的设置；来源游戏退出后刷新共享方案，无需后台轮询。
5. 「恢复同步前设置」恢复上次同步涉及的文件并暂停此实例同步，防止下次启动又覆盖回来。

例如：来源音量 70%，冒险整合包音量 20%。首次预览默认保留 20%；选择采用共享后变为 70%。来源改为 80% 并退出，下次启动冒险整合包会更新到 80%。如果又在冒险整合包单独改成 50%，会保留 50% 并提示差异，不擅自覆盖。

## 范围与文件保护

这是本机、同一游戏根目录内的来源到跟随实例同步，不使用云账号或上传服务。`options.txt` 仅同步选择范围内的已识别字段，目标尚未生成的选项与不兼容的新旧按键编码会跳过；注释、未知字段、原换行以及未勾选的设置保留。不会复制 Java 路径、内存、启动参数、账号、模组配置或存档。

服务器列表按整个 `servers.dat` 文件处理，不自动合并两份不同列表；首次有差异需要在预览中明确选择。保留本地列表时会记住该实例不跟随服务器列表。仅共享服务器时不读取不相关的游戏选项。

来源正在运行时沿用最近保存的共享方案；跟随实例运行时不修改其文件。后台刷新若与安装等任务冲突，留到下一次启动时刷新。同步失败保留原文件并显示原因，不因同步失败阻止游戏启动。复杂版本或模组专用设置仍需结合游戏实际行为确认。

共享方案在启动器数据目录 `settings-sync/<游戏目录摘要>.json`，成员和独立选项在实例 `.fangyu-settings-sync.json`。更新使用文件事务；备份在实例 `.settings-sync-backups/<id>`，包含修改前的文件和 SHA-256。恢复前校验全部备份文件。历史备份会保留在对应实例目录。

## 动效

- 统一交互、页面、展开和主题过渡时长；保留轻微按钮按压回弹与固定阴影之间的透明度过渡。
- 游戏详情标签加入与主导航一致的切换；快速往返或中途关闭动画后恢复正确的可见性和变换状态。
- 向下展开的面板按内容实际高度揭示，不缩放文字；快速展开、收起和反向操作共用当前进度，避免突然跳回初始状态。
- 下载任务完成或失败、保存共享设置、同步结果提供可关闭的页脚提示，带相应查看入口；不遮挡主操作，也不重放历史任务的提示。
- 「设置 → 外观」可选择流畅动画、跟随系统或关闭动画。关闭时自定义页面、展开、弹窗及按钮过渡立即收敛；其他状态反馈保留。

没有新增运行库或网页内核。共享设置编辑器在打开对应页时才创建，首屏不扫描游戏配置；同步在用户操作、启动前和来源游戏退出时执行。
