# 存档中心、定向修复与存储管理（0.6.0-preview.1）

本轮继续使用 C# / Avalonia 与现有任务队列，没有新增运行时依赖。

## 单世界存档中心

游戏库 → 选中游戏 → 存档与备份。页面读取实例 `.minecraft/saves` 中的世界名称、游戏版本、模式、最近游玩时间、占用大小和原有 `icon.png`。没有图标时显示方块；无法读取 `level.dat` 的世界仍可备份。扫描在进入页面时执行，后台统计，并在切换实例时取消旧扫描，不增加首页启动扫描。

选择世界后可单独备份、打开目录、恢复或删除备份。备份以压缩归档、文件大小和 SHA-256 清单保存至启动器数据目录 `world-backups`；排除 `session.lock`。它与原有的整实例快照分开管理。

恢复需确认，先解压到世界目录旁的临时目录，逐项验证大小、哈希和路径；全部通过后，自动备份当前世界，再替换该世界目录。新增文件会随目录替换移除，其他世界不变。已从磁盘移除、但仍有备份的世界也会列出，允许恢复。恢复前自动备份可以像手动备份一样删除，删除前需确认。

备份与恢复进入下载任务中心，支持取消和失败后重试。暂停后保留任务记录，重新开始本次世界操作；此类压缩任务不提供按字节续压缩。取消时清理未完成归档或解压目录，已完成的备份保留。操作前要求关闭对应游戏。

## 定向修复

游戏库 → 游戏详情 → 诊断 → 检查游戏文件。复用版本继承和安装清单，检查本体 jar、依赖库、原生库、资源索引、资源对象及已列出的日志配置。加载器版本检查父版本 jar，不生成重复的子版本 jar。

页面展示缺失 / 大小不符 / 哈希不符的文件及预计下载量。点击修复后，任务执行时重新扫描，仅下载仍异常的文件，下载后再次检查。沿用现有镜像选择、下载校验、暂停及断点机制。不修改版本描述 JSON，不删除模组、配置、世界或自定义资源。

没有可用哈希和大小的现有文件只能标记为未验证；加载器生成的处理结果、没有完整下载信息的库不能据此判断运行正确，必要时重装对应加载器。元数据无法读取时显示错误，不声称修复完成。

## 存储管理

设置 → 存储。手动扫描版本元数据、资源介绍与图标、账号外观、Java 安装包、实例快照、世界备份、Java 运行环境与游戏目录。

可清理分类显示的是**超过 7 天的完整缓存**，不包含新缓存和 `.part` / `.tmp` 文件。确认后重新判断文件时间再删除；存在可恢复或正在运行的任务时，要求先完成或取消任务。保留本地衣柜、所有已安装 Java、游戏共享资源、模组、配置、存档和备份。快照及世界备份在实例页面逐份管理，不一键扫除。

Java 总量包含其安装包缓存，界面会提示不能将各分类重复相加。当前没有卸载未使用 Java、资源对象引用回收或自动清理策略。

## 验证范围

核心检查覆盖 NBT 读取、单世界恢复、其他世界隔离、恢复前备份、取消清理、损坏归档拒绝、备份删除、已移除世界恢复、哈希修复、父版本 jar 与清理边界。桌面检查通过隔离数据和模拟下载执行备份、恢复、修复、设置切换与缓存确认流程，并检查浅色 / 深色和最小窗口页面。

Windows 成品继续交付单文件 EXE；Linux / macOS 尚未实机验收。测试世界与下载服务使用本地夹具，不代表所有真实模组组合均已测试。
