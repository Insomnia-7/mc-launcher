# 资源流程、整合包启动与 Horizon 转换修复

## 已复现的问题与修复

Fresh & Smooth 26.3 的实际安装暴露了原版条件参数数组的读取问题。参数模型现在保留数组，异步解析、序列化重读、加载器合并及占位符展开均覆盖；自定义宽高不会重复添加。

同一整合包中的 EMF 元数据描述含有实际换行。Fabric 的 Gson 解析允许该格式，原来的严格解析未识别出 EMF，随后误报缺少前置并在创建游戏进程之前拦截。修复兼容该描述格式，同时保留真实缺失、冲突及版本不符检查。未采用跳过启动检查的处理。

提供的旧日志没有给出对应整合包的致命异常。启动器现在区分进程创建与可见窗口；Windows 会尝试显示游戏窗口，结束时排空输出并记录实际退出码，不再根据两分钟时长推断失败。关闭后释放监控拥有的进程与日志句柄。

Horizon 转换需要其构建锁定的 Mojang 原始版本文件。原流程先序列化为方隅的版本模型，丢失字节一致性，触发上游 SHA-1 拒绝。现在从 [Horizon 锁定文件](https://github.com/horizon-rust/horizon/blob/main/research-lock.json) 读取所需版本和哈希，从 Mojang 官方包地址获取并校验原始字节，安装匹配资源后恢复原始文件再转换。保持原有账号拥有权验证，不在命令行或日志传递账号密钥。

## 界面和代码清理

- 已安装资源的所选发布版本显示“启动游戏”，启动实际目标实例；重新进入项目从磁盘恢复状态，选择其他版本或删除实例后恢复安装。
- 新建实例直接进入发现资源的游戏本体栏目。删除旧的 Avalonia 弹窗、WPF FirstRunView 及专用向导视图模型，调整旧入口和检查以保持可编译。旧下载任务的 setup 执行分支继续保留，以兼容已存在的断点任务。
- 导航更名为发现资源、下载进度。实例列表、卡片和详情区提供删除入口，沿用删除确认和可选自动 Java 清理。
- 删除无引用且此前已排除打包的旧背景图 world-meadow-v2.png（1,783,450 字节），清理旧窗口专用引用。该图片此前未打入 EXE，不将它的体积算作 EXE 缩减。

## 验证范围

使用从官方来源下载的 D 盘隔离测试数据，不复制或修改用户真实游戏目录、账号或存档。

实际测试包含 Minecraft 26.3 可见窗口和正常退出、Modrinth 的 Fresh & Smooth 26.3 指定 Fabric 发布版本的安装后启动按钮、实际窗口和正常退出，以及 Horizon 官方签名 Nightly 的完整资源转换和完整性检查。Rust 实际游戏会话、微软登录和世界游玩不在本批已通过范围。

自动审批曾拒绝复制真实游戏库用于测试，理由为超出日志排查授权；后续全部真实资源测试改用官方重新下载的隔离资料。

本批优先 Windows；保留跨平台核心和现有其他平台入口，不宣称 Linux/macOS 获得本批实测。
