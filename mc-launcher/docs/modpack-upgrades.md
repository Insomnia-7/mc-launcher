# 整合包升级工作区 · 0.8

游戏库打开整合包，进入「整合包更新」。新下载的 Modrinth / CurseForge 实例会记录项目和发布版本；点击「检查平台版本」，按正式版、测试版、开发版筛选，再选择「预览更新」。CurseForge 需要可用的 API Key，禁止第三方分发的文件应由用户下载后选择本地包。

旧实例和本地导入的整合包可以选择新版 `.mrpack` / CurseForge `.zip`。0.8 以前没有文件基线的实例不会猜测哪些旧文件可以删除：重名冲突默认保留本地，用户需要核对并处理旧模组。该首次升级不会追溯补写平台项目来源。

## 文件比较与恢复

导入时在实例目录记录 `.fangyu-pack.json`，包含整合包原始文件的 SHA-256、大小、平台来源，以及小于等于 512 KiB 的 JSON 原文。升级将原始内容、本地现状和目标整合包进行比较：

- 本地未修改：自动选择新增、更新或移除整合包自带文件。
- 上游未修改：保留本地修改与本地删除。
- 两边独立修改 JSON 对象的不同字段：自动合并；数组作为整体，不按下标猜测合并。
- 同字段修改、普通文本和二进制冲突：默认保留本地，允许逐项选择采用新版。
- 不在原始清单里的用户新增内容不会自动移除。存档、截图、日志、服务器列表、本地皮肤和隐藏状态文件不参加整合包更新。

「预览」会下载并校验目标文件，在游戏根目录 `.cache/pack-updates/<id>` 暂存，不修改实例。应用时重新核对实例、完整模组目录和暂存文件；准备共享游戏/加载器依赖后再次核对。文件替换、移除、实例版本和基线更新使用同一个回滚事务。升级前文件保存在实例 `.pack-backups/<id>`；「恢复更新前」校验备份后恢复上次升级涉及的文件，不改动存档。

整合包回退不能回退游戏已改写过的世界格式。因此首次用新版 Minecraft 打开旧世界前，应在「存档与备份」中单独备份世界。

升级和恢复进入持久任务中心。暂停保留暂存，取消清理暂存；已完成的共享依赖保留。应用失败可以重试；实例已改变时需取消旧任务并重新预览。未完成任务引用的预览不会被重新准备操作覆盖。

## 模组兼容检查

「日志与诊断 → 实例体检」及启动前读取已启用 JAR 的 Fabric、Quilt、Forge、NeoForge 常见元数据，检查重复 ID、必需前置、常见版本范围和明确声明的互斥关系。包含声明的内嵌 JAR；禁用文件与 Fabric 服务端专用模组不参与客户端依赖检查。桥接加载器、复杂条件及无法比较的版本表达式提供提示，不猜测为不兼容。

明确的依赖错误会引导至诊断页。检查不联网、不自动删除模组，也不能保证模组运行逻辑一定兼容。下载与内核安装仍使用现有实现。

## 界面与队列

Modrinth 整合包详情采用原色项目图标和封面、介绍、独立「版本与安装」入口。介绍为纯文本摘要，截图按比例裁切、限宽解码并释放；封面失败不影响安装，未加入浏览器运行环境。CurseForge 提供基础介绍和默认插画。

任务中心默认完成后接续最早的等待任务，可关闭并保存偏好；等待任务可提前或延后。失败、暂停、取消和程序关闭会停止本轮自动接续。程序重开不擅自恢复中断任务。
