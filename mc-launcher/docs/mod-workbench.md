# 模组工作台与试装副本（0.5.0-preview.1）

本轮交付批量模组管理、更新变更预览和独立试装副本，继续使用 C# / Avalonia 与现有下载器、实例快照和持久任务机制，没有增加界面运行库。

## 使用方式

进入游戏详情 → 模组与资源：

1. 勾选本地模组，可以全选、批量启用、停用、删除或重新安装。删除前显示确认；每批变更执行前自动保存实例快照。
2. 选择更新频道并检查兼容更新，勾选要处理的项目，点击「预览所选更新」。
3. 预览显示当前与目标版本、正式 / 测试 / 开发频道、更新日志、要补充的必需前置和下载大小。
4. 展开「选择目标版本 / 调整更新项目」，可更换适配当前游戏版本及加载器的发布版本。更换版本或取消项目后，旧计划失效，重新生成预览才可执行。
5. 选择「备份并应用到当前实例」，或设置副本名称与是否复制存档，选择「创建试装副本后应用」。

精确重装要求文件仍匹配已记录的上游项目、发布 ID 和哈希。无法确认来源或文件已经被修改时，不猜测应下载哪个文件，界面会提示从发现资源重新选择。停用文件重装后仍保持停用状态。

本轮处理已安装模组的更新和重装；整合包整体版本升级及本地配置三方合并属于后续能力。

## 安装计划与一致性

生成预览仅请求版本元数据，不下载模组正文，不替换现有文件。计划固定项目、发布版本、目标文件、来源、大小与上游提供的校验信息。

共享必需前置按项目 / 版本去重；对已有且满足可核实要求的前置继续沿用。指定版本之间发生冲突、启用模组依赖已停用前置、缺少兼容发布、文件名碰撞等情况，会阻止生成计划。深层依赖中的不同指定版本也会报告冲突。

计划记录当前环境与模组文件集合指纹。执行前及下载校验后再次检查；用户或其他程序更改了文件，旧计划将被拒绝，需要重新预览。所有待提交文件先下载到暂存目录并校验，再以一次文件事务提交文件和来源记录。下载失败不改动旧文件，提交失败回滚本批已提交的改动。

预检依据平台声明、版本信息和文件状态；没有将其表述为所有模组运行逻辑均兼容。更新日志按文本展示，过长内容截断。

## 副本行为

从游戏详情概览或「••• → 创建试装副本」进入复制选项。可分别选择模组、设置与配置、资源包、光影、存档、截图和服务器列表；默认不复制存档和截图。

副本沿用原 Minecraft / 加载器版本，使用新的实例 ID 和独立目录。只复制所选的私有内容，不复制启动器账号库、日志、下载缓存或共享游戏资源，不使用指向原配置 / 存档的硬链接。原版或加载器实例的副本不会被误标成整合包。

先复制到任务暂存区，按清单校验文件，完成后再将目录移入实例目录并登记。暂停后保留清单和已完成文件，恢复时核对来源并复用匹配的副本文件。复制过程中原文件改变会停止发布半成品。

「创建试装副本后应用」必须复制模组和配置，随后将同一变更计划应用到副本，原实例不变。若在副本完成后暂停更新，已完成的副本仍可在游戏库查看。

## 暂停、取消与恢复

批量变更、复制和试装更新均通过下载任务中心记录。暂停保留暂存文件；恢复使用原任务参数、发布版本与计划。取消清理尚未完成的暂存下载 / 复制文件；已经完整创建的副本保留，可由用户在游戏库删除。

操作前的快照可从「存档与备份」恢复。变更计划和任务记录保留在启动器数据目录，分别位于 `mod-plans/` 与 `task-center/`，用于恢复与查看历史。

## 验证

核心检查覆盖共享依赖去重、元数据冲突、变更计划保存恢复、来源校验、批量启停删重装、损坏下载、事务失败回滚、快照恢复、原版副本识别、复制选项与独立性，以及任务暂停 / 恢复 / 取消。界面检查覆盖确认流程、版本选择、变更预览、试装更新与 900×640 窗口。

Windows x64 继续交付自带运行环境的精简压缩单 EXE。Linux / macOS 本轮没有实机验收，Native AOT 仍属于后续独立实验。
